# 2026-08-28

- 修复战报面板无法上下滚动的问题（`scripts/ui/BattleLogUI.gd`）：
  - 第一次尝试：仅把 `log_label` 的 `mouse_filter` 从 IGNORE 改为 PASS —— 无效。
  - 根因：父容器 `BattleLogUI`(Control) 自身是 `MOUSE_FILTER_IGNORE`，Godot 命中测试会跳过整棵子树，子节点永远收不到鼠标事件。
  - 最终修复：父容器 `mouse_filter` 改为 `PASS`（自身无 size 不会被命中，但允许命中测试进入子树），`log_label` 保持 `PASS`。滚轮可滑动，点击仍穿透给战场。
  - 教训：Godot 中若父节点 mouse_filter=IGNORE，改子节点无效；滚动类控件要能响应滚轮，父链上不能有 IGNORE 节点阻断命中测试。
- 战报滚动仍失效的二次根因（最终修复）：
  - 真正根因不在 UI 本身，而在 `MainScene._input` 全局滚轮处理：第 1185-1195 行 `_input` 先于 `_gui_input` 执行，当鼠标在战报上时 `_is_pointer_over_interface` 返回 false（未包含战报区域），于是滚轮被当作"战场缩放"处理并 `set_input_as_handled()`，导致 RichTextLabel 永远收不到滚轮。
  - 修复：在 `MainScene` 加 `battle_log_ui` 成员引用；`_is_pointer_over_interface` 追加 `battle_log_ui.is_pointer_over_log(pos)` 判断；`BattleLogUI` 新增 `is_pointer_over_log(pos)` 方法（用 `log_label.get_global_rect().has_point(pos)`）。鼠标在战报上时跳过地图缩放且不标记已处理，事件正常走到 RichTextLabel 完成滚动。
  - 教训：Godot 中 `_input` 优先级高于 `_gui_input`，若 `_input` 里 `set_input_as_handled()` 会阻断 GUI 控件接收事件；自定义 GUI 区域要响应滚轮，必须确保全局 `_input` 不会抢先吞掉该区域的滚轮事件。
